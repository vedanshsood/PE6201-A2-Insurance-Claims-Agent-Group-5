PART1 Why an Agent

1.1 Ladder Placement For Problem A’s health-insurance claim triage, our architecture is placed at Rung 7 (Agent) on Class 4’s autonomy ladder. Lower rungs (Rungs 1–6: single calls, prompt chains, routing classifiers, parallel fans, orchestrators, and evaluator-optimisers) define enumerable, static workflows. They fail in claim adjudication because incoming claims feature non-linear, unpredictable branching across arbitrary line items, specific exclusions, and documentation criteria that hard-coded execution graphs cannot anticipate. However, an unconstrained Rung 7 agent introduces severe financial and regulatory risks, such as premature payout authorizations, hallucinated policies, or prompt injection via claimant narratives. To reconcile autonomy with corporate governance, we bound our ReAct loop with strict deterministic code-level guardrails (MAX_TURNS=8, TOKEN_BUDGET=60,000, action de-duplication) and enforce human-in-the-loop gating (AUTONOMY="confirm" on issue_decision_letter). 

1.2 Workflow Test and Agentic Conditions The claims environment satisfies both agentic criteria. First, execution trajectories cannot be scheduled beforehand: chasing pre-authorisations via get_preauthorisation is strictly conditional on the authoritative requires_preauthorisation boolean returned dynamically by check_coverage. Second, the loop receives machine-speed structured truth from deterministic local records rather than generating ungrounded assumptions. The four-question workflow test confirms that turn count varies dynamically with input—terminating in two turns on lapsed policies, but spanning four to six turns on complex multi-procedure claims. 

1.3 Ground-Truth and Reliability Tests Problem A satisfies the ground-truth speed test: five local JSON fixtures (members, policies, procedures, preauthorisations, and hospitals) answer in milliseconds, objectively falsifying invalid claims. Multi-turn execution subjects the agent to compounding reliability decay, where end-to-end success follows P = s^T, or s = P^(1/T). In our live V2 evaluation using qwen/qwen-2.5-72b-instruct, the agent achieved a measured pass rate of P = 88.33% (53 passing trials out of 60) across an average horizon of T = 5.47 tool calls (328 total calls across the battery). This derives an empirical single-step reliability of: s = (0.8833)^(1 / 5.47) ≈ 0.9776 (97.76%) 

Because each failure escalates to a human assessor costing US$7.60, reducing trajectory length directly minimizes Layer 2 fallback penalties. 

1.4 What Good Looks Like In production, a successful system requires: (1) factual grounding against official records without fabricated coverage; (2) deterministic compliance with the three canonical outcomes (approve_in_principle, request_document, or escalate); (3) executing the irreversible write (issue_decision_letter) at most once, strictly after full evidence resolution and confirmation; (4) unconditional escalation on hostile narrative injections or limit breaches; and (5) an operational cost per successful task strictly below the US$7.60 human benchmark.
